## Показанный результат

- В каталоге ~/docker-one-app ученик вручную ввёл app.py через Vim. Скриншот 18:48 с cat app.py подтверждает сохранённый файл. До этого разобраны вызов внешней команды через :!wq (shell exit 127) и E45/readonly; сохранение выполнено после подсказки :wq!.
- Приложение использует HTTPServer/BaseHTTPRequestHandler, класс App с do_GET, JSON с service=lab-info и version=1.0, слушает 0.0.0.0:8000; serve_forever поддерживает цикл обработки запросов. Показанный перевод строки внутри JSON перед закрывающей } допустим как пробельный символ. Это не отдельный дефект JSON.
- Скриншот 19:00 показывает конец сборки: COPY app.py ., CMD ["python", "app.py"], Successfully built 0ee63dec8d25 и Successfully tagged lab-info:v1. Полный Dockerfile отдельно не показан: FROM python:3.14-alpine и WORKDIR /app были даны в учебном шаблоне; наличие их именно в сохранённом файле не утверждается только по хвосту сборки.
- ss -ltnp с фильтром порта 8145 показал только заголовок. Затем docker run -d --name lab-info -p 127.0.0.1:8145:8000 lab-info:v1 вернул ID 348461c329b7fc0150b53a678b8e8db32d3258899363250410eb4ae170ddb9ed.
- docker ps -a показывает lab-info, образ lab-info:v1, команду python app.py, Up 9 seconds и 127.0.0.1:8145->8000/tcp. Старые Compose web/proxy в этом же снимке имеют Exited (0). Другие старые контейнеры также показаны остановленными; это не команда на их удаление.

- docker logs lab-info содержит 172.17.0.1, [17/Oct/2026 16:59:50] и "GET / HTTP/1.1" 200. Наличие этой записи связывает клиентский запрос с обработкой приложением.
