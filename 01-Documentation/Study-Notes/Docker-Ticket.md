# TASK-013 — Первый контейнерный веб-сервис

Тип: учебное развёртывание, не скрытый инцидент. Время: 20–30 минут после
проверки окружения. Статус: зачтено с подсказками 30.09.2026; [мой отчёт](Docker-Report.md).

## Задача

Запустить Nginx в Docker на Ubuntu VM и доказать, что ответ приходит от
созданного контейнера. Системный Nginx устанавливать не нужно.

| Параметр | Требование |
|---|---|
| Место выполнения | Ubuntu `linux01`, SSH-сеанс |
| Имя нового контейнера | `s18-web` |
| Образ | Docker Official Image `nginx:1.30.5-alpine` |
| Режим | В фоне, без автоматического удаления |
| Публикация | Только `127.0.0.1` Ubuntu, порт `8133` → порт `80` контейнера |
| URL клиента | `http://127.0.0.1:8133/` из Ubuntu |
| Ожидаемый ответ | HTTP 200 и стандартная страница «Welcome to nginx!» |

Исходно были предложены s13-web и stable-alpine. В моей попытке использованы
s18-web и nginx:1.30.5-alpine; скачивание и запуск показаны на скриншотах.
Имя s18-web не меняет номер сессии. Ниже сохранены условия упражнения,
а не требование повторить запуск. inspect отдельно не показан.

## Начало: только проверка окружения

```bash
docker version
```

Пришли вывод. Если отсутствует команда, недоступен daemon или запрещён доступ
к socket — сначала разберём именно это. Не переустанавливай Docker вслепую.

Когда Engine доступен, проверь до создания:

- нет ли уже контейнера с именем `s18-web` (`ps -a`);
- свободен ли порт 8133 (проверка через `ss`, плюс существующие Docker-публикации).

Если имя или порт заняты, остановись и покажи результат: чужие объекты не
удалять. Затем составь `run` по формулам в теории и параметрам таблицы.
Если нужна полная команда — попроси, это знакомство с инструментом, не экзамен.

## Приёмка

1. Контейнер работает, имя и образ соответствуют заданию.
2. `docker ps` (или отдельная проверка `docker port`) показывает публикацию только на `127.0.0.1:8133`.
3. Ограниченный по времени curl из Ubuntu возвращает HTTP 200 и нужную страницу.
4. В логах контейнера виден твой запрос.
5. Останови **только `s18-web`**: объект остаётся в `ps -a`, URL перестаёт отвечать.
6. Запусти тот же контейнер через `start`: HTTP восстановился, ID не изменился.
7. Сохрани ID контейнера/образа, публикацию и результаты проверок в отчёт.

Автоматического чекера пока нет: приёмка по этим наблюдениям и двум вопросам
из теории. Результат и границы подтверждения записаны в отчёте.

## Границы

Не трогать старые systemd-службы и чужие контейнеры; не использовать prune,
`--privileged`, host networking, mount Docker socket или корня хоста.
Не менять UFW и не добавлять пользователя в docker-группу ради обхода ошибки.
С Mac его localhost — это Mac, а не Ubuntu: клиентские проверки выполняются в SSH.

Финальная остановка предложена, но не подтверждена. После приёмки останови только созданный `s18-web`, чтобы лаборатория не
оставляла лишний работающий процесс. Удаление контейнера/образа обсудим отдельно.
